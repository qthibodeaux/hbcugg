Downstream effect: `2-schools/roster_hub_2025.json`'s `teams.swacmvsu.physical.by_position_group` has `weight_coverage: 0` and `weight_avg: null` on every position group, while `height_avg`/`height_coverage` are populated normally. **Fix:** re-scrape/re-source MVSU's roster weight data specifically; once `player_seasons_2025.json` has real per-player weights for MVSU, the `roster_hub` aggregation should pick it up automatically since the aggregation logic itself isn't the problem — only this one team's source data is.
- [ ] **`roster_hub_2025.json`'s `transfers.transfer_count` / `transfer_rate` is drastically undercounting real transfers, league-wide.** Verified against `3-players/player_seasons_2025.json`: for nearly every team, far more players carry a real (non-null) `transfer_tier` than are flagged `is_transfer: true` — e.g. Norfolk State has 101 players with a `transfer_tier` but only 50 marked `is_transfer: true`; Alabama State 118 vs 44; Florida A&M 107 vs 69; Alabama A&M 119 vs 63; Texas Southern 97 vs 44; Grambling 98 vs 51; SC State 92 vs 45. `roster_hub`'s team-level `transfers.transfer_count` tracks the under-set `is_transfer` boolean (matches it almost 1:1, e.g. Norfolk State hub count is 51, right next to the 50 `is_transfer=true` players, not the 101 with a real tier), not the more complete `transfer_tier` signal — so every team's transfer count/rate shown in the Rosters Hub is roughly half what the tier data implies it should be. Separately, `meacdsu` (Delaware State) has its own smaller anomaly: `hub.transfer_count` is 1 even though 4 players are flagged `is_transfer: true` there — worth checking whether that's the same root cause or a distinct one-off. **Fix:** either correct `is_transfer` to be set consistently with `transfer_tier` at the source, or have the `roster_hub` aggregation count "has a transfer_tier" as the transfer signal instead of (or in addition to) `is_transfer`, whichever field is actually meant to be authoritative.
